# 通用图像 RAG：使用与优化思路

本轮只优化知识检索。曝光数值、目标框和可靠性仍由当前图片的视觉工具产生；资料和历史不能代替它们。

## 如何查看

启动项目后打开 **http://127.0.0.1:7860/knowledge**，无需上传图片或配置云端密钥。

1. 保持“当前发布配置”，输入一个问题，点击“对比检索”。
2. 查看三列中的知识库版本、检索方法、阈值、评测状态、原句及来源位置。
3. 要检查知识补充的效果，可手动选择 **G0 原有知识** 或 **G1 补充知识**。手动实验选项不表示已获准替换默认配置。
4. “未交付知识片段”表示当前阈值下没有依据；“不可用”表示模型、依赖或索引有问题，两者不同。自动降级时会显示原因。

建议尝试：

- “为什么检测框变多，仍不能说识别更准确？”
- “22类满足校准条件，是否意味着每类都达到80%精度？”
- “浮点图计算SSIM时为什么需要设置data_range？”
- “开发集有没有校正后误报变少、漏报却增加的例子？”

页面只检索资料，不生成大模型解释，不调用付费API。要让对话工具引用资料，可在 `/agent` 提出需要依据的任务；这属于另一个执行流程，其回答质量没有由本次检索评测证明。

## 实现

```text
中文问题
  → 固定本会话的语料、模型和阈值版本
  → TF-IDF / 本地BGE / 等权RRF融合
  → 拒绝阈值过滤
  → 最多交付top_k个真实片段及来源
```

| 部分 | 本轮实现 |
|---|---|
| G0 | 原3份资料、14个片段，原片段不改写 |
| G1 | 原片段加8张知识卡，11份资料；项目实测、工程规则、研究分别标记 |
| 分段 | 正文最多400字符、重叠最多80字符；引用保存原句与Unicode字符位置 |
| TF-IDF | 字符2—4元组，保留现有计算方式 |
| Embedding | 本地`BAAI/bge-small-zh-v1.5`，512维归一化向量；查询使用官方检索指令 |
| Hybrid | 两路分别取前20，等权RRF、常数60；RRF分数不是正确概率 |
| 缓存 | 语料哈希、模型资产、方法、阈值和查询分别绑定；旧会话保持创建时快照 |
| 发布 | `knowledge/general_rag_release.json`记录实际默认配置及采用理由 |

已有 `search(query, top_k=3)` 和原构造方式保留。网页工厂读取发布配置；直接使用旧构造器仍得到原v1基线。无Torch的轻量入口可以使用TF-IDF；显式Embedding/Hybrid实验缺依赖时明确不可用。

## 为什么这样评测

80题先按来源编写，再独立审题，最后冻结。每个事实的改写留在同一集合，开发与保留测试各40题：旧知识20、新知识10、未知信息10。标签不会加入检索索引，也不会发送给模型。

同一题可能需要多组证据：Recall按证据组计算，重叠片段中的同一事实只算一次；MRR计算首条相关结果的位置。无答案题独立计算误返回率。可回答的能力边界问题，不会因为答案包含“不支持”就被当成无答案。

实验分三层：**同语料比较算法、相同固定阈值比较知识补充、另列开发集调阈值的效果**。两种语料的主表都使用30道可回答题，另列旧20题与新10题，避免混用分母。五次计时重复仅用于速度测量。

方法和阈值只在开发集选择。保留集运行前固定候选；未达约定门槛就保留当前默认值，不能看完测试再改选另一个最好方法。标签为模型编写并经同模型家族独立代理暂定审核，未经外部人工验收；80题是小规模项目评测。

## 复现入口

运行本地结构检查（不加载Embedding）：

```powershell
python -m optical_agent.experiments evaluate_general_rag validate
```

完整实验分为`prepare → dev → test → report`，使用独立的新运行目录。`prepare`必须提供真实独立审核产生的`--review-file`，审核记录绑定题集SHA256；不要手工伪造“审核通过”。所有模型、原文、索引及原始排名保存到 `D:\CodexData\optical_agent\rag\general_v061`。

输入、索引或模型发生变化后，原运行会拒绝继续；测试结果不能覆盖。旧水下C0/C1题集、语料和成绩保留原含义。
